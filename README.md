# Rspack Bench

Стенд для сравнения скорости production-сборки Rspack и webpack на синтетическом TypeScript-проекте.

## Запуск

```bash
npm run bench:generate         # сгенерировать 2000 модулей в bench/src
npm run bench:generate -- 5000 # или другое количество
npm run bench                  # замер, 3 прогона на каждый режим
npm run bench -- 5             # или другое число прогонов
```

Отдельные сборки: `npm run bench:rspack`, `npm run bench:webpack`.

## Что генерируется

- Дерево TS-модулей (каждый импортирует два дочерних), похожее на дерево компонентов.
- Общий слой утилит `shared/`, который импортируют все модули.
- Импорты из `lodash-es` и CSS-файл на каждый десятый модуль.

## Что замеряется

| Режим | Что это |
|---|---|
| Холодная сборка | без кеша, как первая сборка в CI |
| Первая сборка с записью кеша | без кеша, но с сохранением его на диск |
| Повторная сборка с кешем | кеш на диске уже есть, исходники не менялись |

Время — медиана, включая запуск Node и CLI.

## Насколько честное сравнение

Обе сборки делают одно и то же: компилируют TS, выносят CSS в отдельный файл, минифицируют JS и CSS.
Webpack настроен на нативный esbuild (`esbuild-loader`), а не Babel + Terser,
поэтому сравниваются сами сборщики, а не JS-трансформеры. С типовой конфигурацией
на Babel и Terser webpack будет ещё медленнее.
